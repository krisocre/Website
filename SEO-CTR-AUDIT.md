## On-page and search appearance checks

- The homepage H1 stays focused on Google review removal in Canada. Its visible pricing copy explains that the assessment is free and approved work costs CAD $50 upfront per review plus $125 only for each review successfully removed. The existing hero, pricing calculator, assessment buttons, page sections and working URLs remain in place.
- The homepage points to the **Review checker** and **Guides** in the main navigation. Its reporting card leads with the report-status intent. The price guide link states that it shows different cost outcomes. The appeals guide answers “What does ‘appeal eligible’ mean?” at its existing anchor and links to the five-step evidence checklist. These are crawlable HTML links. Google chooses whether to display organic sitelinks. [Google’s sitelinks guidance](https://developers.google.com/search/docs/appearance/sitelinks)
- The branded white R on the navy favicon is a square SVG with a 64 × 64 viewBox. The canonical homepage already links to it. Live `/favicon.svg` returned HTTP 200 as `image/svg+xml`. Live robots.txt allows crawling and the icon had no restrictive X-Robots-Tag. The favicon URL and asset were preserved. Eligibility does not confirm display in Google results. [Favicon guidance](https://developers.google.com/search/docs/appearance/favicon-in-search)
- Homepage WebSite, Organization and Open Graph use **ReviewRemoval** consistently. WebSite now includes `ReviewRemoval.ca` as the alternate name and retains the canonical homepage and publisher reference. Article headlines and breadcrumb leaf labels use the visible H1. Breadcrumb links name canonical destinations. The SEO checks verify the graph and that the pages contain no Review or AggregateRating markup. [Site name guidance](https://developers.google.com/search/docs/appearance/site-names) · [Breadcrumb guidance](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb)

## Search Console measurement after publishing

1. Record the deployed date and capture the pre-change Search Console baseline before release. Use Web search and Canada, with separate Desktop and Mobile views. Preserve the dates, filters, URLs and export files.
2. Use URL Inspection to confirm Google crawled the updated canonical pages. Check the homepage, reporting and appeals, rating study, checker, removal statistics and pricing first. Record the title link and snippet observed for representative searches, along with device and date. Google can show different wording for other queries.
3. Compare two complete 28-day windows with the same weekday mix. Use a pre-deployment window and a post-recrawl window. Keep the dates out of partial reporting days. Extend both windows equally if the top cohorts have few impressions.
4. Match the same canonical page, query or predeclared query group, country and device. Compare separately in average-position bands **1–3**, **4–10**, **11–20** and **21+**. Report cohorts that moved position bands apart from like-for-like comparisons. Track brand queries separately from buying, pricing, appeal/status, evidence/tool and research queries. The UI supports fixed page and device filter exports. The Search Analytics API can return query, page, country and device together. [Search Console performance reports](https://support.google.com/webmasters/answer/7576553?hl=en) · [Search Analytics API](https://developers.google.com/webmaster-tools/v1/searchanalytics/query)
5. Calculate each cohort’s CTR as total clicks divided by total impressions. Report clicks, impressions, CTR percentage-point change and average position alongside the sample size. Keep overall page totals separate from visible query rows, since Search Console may omit some queries. A change on a handful of impressions is directional.
6. Review organic assessment submissions and qualified leads alongside the CTR cohorts. Keep the homepage and price guide as separate commercial groups. Use the existing measurement and attribution data, and verify that additional clicks are reaching the paid-service funnel.
